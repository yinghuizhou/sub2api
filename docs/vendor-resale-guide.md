# 供应商采购与二次转售系统 — 使用教程

## 1. 系统概述

Sub2API 供应商系统允许你从第三方低价 API 转发站（如咸鱼/淘宝上的转发服务）采购 API 额度，整合到平台统一出售。自有高成本账户作为兜底备用。

核心流程：采购供应商 API Key → 录入系统 → 自动调度转发 → 赚取差价

## 2. 快速开始（5 分钟上手）

### 2.1 启用供应商系统

1. 进入 管理后台 → 系统设置
2. 找到「供应商系统」区域
3. 开启「供应商系统总开关」(vendor_system_enabled)

### 2.2 添加第一个供应商

1. 进入 管理后台 → 供应商管理
2. 点击「添加供应商」
3. 填写基本信息：
   - 名称：如 "低价Claude转发-A站"
   - API 格式：选择 Anthropic 或 OpenAI（取决于供应商的 API 格式）
   - Base URL：供应商的 API 地址，如 `https://ai.9w7.cn`
   - 认证类型：通常选 `api_key`
   - 计费模式：根据供应商的收费方式选择
4. 保存

### 2.3 创建供应商账户

1. 进入 管理后台 → 账号管理
2. 点击「添加账号」
3. 关键字段：
   - 平台：选 `claude`
   - 类型：选 `api_key`
   - 凭证：填入从供应商获取的 API Key
     ```json
     {
       "api_key": "sk-xxx-your-vendor-api-key",
       "base_url": "https://ai.9w7.cn"
     }
     ```
   - 供应商：选择刚创建的供应商
   - 来源类型：自动设为 `vendor`
4. 将账户加入一个分组（如"低价转发池"）

### 2.4 配置调度策略

1. 进入 管理后台 → 分组管理
2. 创建两个分组：
   - "低价转发池"（主力）— 放供应商账户
   - "自有账户池"（兜底）— 放自有高成本账户
3. 将"自有账户池"设为"低价转发池"的 fallback_group_id
4. 用户的 API Key 默认分配到"低价转发池"

这样用户请求会优先走供应商账户，全部不可用时才 fallback 到自有账户。

## 3. 供应商管理详解

### 3.1 API 格式

| 格式 | 说明 | 适用场景 |
|------|------|----------|
| anthropic | 供应商 API 兼容 Anthropic 官方格式 (/v1/messages) | 大多数 Claude 转发站 |
| openai | 供应商 API 使用 OpenAI 兼容格式 (/v1/chat/completions) | 部分通用转发站 |

选择 `openai` 格式时，系统会自动做 Anthropic ↔ OpenAI 协议转换。

### 3.2 认证类型

| 类型 | 说明 | 请求头 |
|------|------|--------|
| api_key | 标准 API Key 认证 | `x-api-key: sk-xxx` |
| bearer | Bearer Token 认证 | `Authorization: Bearer sk-xxx` |
| session | Cookie Session 认证 | `Cookie: session=xxx` |

### 3.3 计费模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| token | 按 token 用量计费 | 类似官方 API 的按量付费 |
| quota | 固定额度包（充多少用多少） | 咸鱼上常见的充值模式 |
| subscription | 时间订阅制（月卡/周卡） | 包月不限量或有上限 |

### 3.4 额外请求头

某些供应商可能需要额外的请求头。在「额外请求头」字段中以 JSON 格式填写：

```json
{
  "X-Custom-Header": "value",
  "X-Channel": "resale"
}
```

### 3.5 自定义 API 路径

如果供应商的 API 路径不是标准的 `/v1/messages` 或 `/v1/chat/completions`，可以在「API 路径覆盖」中指定，如 `/api/v1/chat`。

## 4. 健康监控

### 4.1 启用健康检查

在供应商编辑页面：
1. 开启「健康检查」开关
2. 设置检查间隔（默认 300 秒 = 5 分钟）
3. 设置检查用的模型（默认 claude-sonnet-4-20250514）

系统会定期向供应商发送一个最小请求来检测可用性和延迟。

### 4.2 健康状态

| 状态 | 含义 | 颜色 |
|------|------|------|
| ok | 正常，延迟 < 10s | 绿色 |
| slow | 可用但延迟 > 10s | 黄色 |
| error | 返回错误（5xx） | 红色 |
| timeout | 请求超时 | 红色 |

### 4.3 自动暂停

连续失败 5 次后，系统自动将供应商状态设为 `error`，其下所有账户停止调度。恢复后需手动将状态改回 `active`。

## 5. 余额管理

### 5.1 余额预警

1. 在供应商编辑页面开启「余额预警」
2. 设置预警阈值（如 5 USD）
3. 余额低于阈值时，系统日志会输出警告

### 5.2 自动暂停

- 额度包模式：已用额度 >= 总额度时自动暂停
- 订阅模式：到期时间已过时自动暂停

### 5.3 手动更新余额

在供应商列表页点击「刷新余额」按钮，或在编辑页面手动更新余额字段。

## 6. 成本分析

### 6.1 设置成本

在供应商编辑页面填写：
- 每千输入 token 成本（USD）
- 每千输出 token 成本（USD）

### 6.2 利润计算

利润 = 用户付费（按你的定价）- 供应商成本（按采购价）

建议利润率：30%-50%

## 7. 协议转换

### 7.1 Anthropic → OpenAI 转换

当供应商 API 格式为 `openai` 时，系统自动处理：

| Anthropic | OpenAI |
|-----------|--------|
| messages[].content (content blocks) | messages[].content (string/array) |
| system (top-level) | messages[0] with role=system |
| max_tokens | max_tokens |
| stop_reason | finish_reason |
| input_tokens/output_tokens | prompt_tokens/completion_tokens |

SSE 流式响应也会自动转换。

## 8. 自动化功能（高级）

### 8.1 自动定价

开启 `vendor_auto_pricing_enabled` 后，系统会根据供应商成本自动计算建议售价。

### 8.2 自动采购（Phase 3）

开启 `vendor_auto_purchase_enabled` 后，系统可以：
- 检测余额不足的供应商
- 自动触发补货流程

注意：自动采购需要对接具体的支付接口，目前为框架代码。

### 8.3 供应商发现（Phase 3）

系统可以 AI 驱动地扫描市场发现新的低价供应商。目前为框架代码，后续版本实现。

## 9. 常见问题

**Q: 供应商账户和自有账户有什么区别？**
A: 功能上完全一样，都是 Account。区别在于供应商账户有 vendor_id 关联，方便管理和成本追踪。

**Q: 供应商 API 返回 429 怎么办？**
A: 调度器会自动 failover 到同 Group 的其他供应商账户，全部不可用时 fallback 到自有账户 Group。

**Q: 如何测试供应商是否可用？**
A: 在供应商列表页点击「测试」按钮，系统会发送一个测试请求并显示结果。

**Q: 支持哪些平台的供应商？**
A: 目前主要支持 Claude API 转发站。后续会扩展到 OpenAI、Gemini 等平台。

**Q: 如何批量添加供应商账户？**
A: 在供应商详情页使用「批量创建账户」功能，一次性添加多个 API Key。

## 10. 故障排除

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 供应商账户无法转发 | base_url 配置错误 | 检查供应商的 Base URL 是否正确 |
| 返回 401 | API Key 无效或过期 | 检查凭证中的 api_key 是否正确 |
| 返回乱码 | API 格式选错 | 确认供应商是 Anthropic 还是 OpenAI 格式 |
| 健康检查一直失败 | 网络不通或供应商宕机 | 检查服务器能否访问供应商 URL |
| 余额不更新 | 计费模式不匹配 | 确认计费模式与供应商实际收费方式一致 |
