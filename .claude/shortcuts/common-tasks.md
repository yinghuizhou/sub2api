# 常见任务快捷方式

这个文件定义了常见任务的标准化流程，让 Claude 能够快速理解你的意图。

## 使用方法

直接对 Claude 说这些短语，它会自动执行对应的完整流程。

---

## 开发任务

### "开始新功能"
```
1. 检查当前分支（必须是 dev）
2. git pull gitee dev
3. 询问功能名称
4. 创建功能分支（可选）
5. 准备开发环境
```

### "修复 Bug"
```
1. 询问 Bug 描述
2. 搜索相关文件
3. 读取文件内容
4. 分析问题
5. 提出修复方案
6. 执行修复
7. 运行测试验证
```

### "优化性能"
```
1. 询问要优化的模块
2. 分析当前实现
3. 识别瓶颈
4. 提出优化方案
5. 实施优化
6. 性能对比测试
```

---

## 文件操作

### "修改 [文件名]"
```
自动流程：
1. Glob 搜索文件
2. Read 读取内容
3. 等待用户说明要修改什么
4. Edit 执行修改
```

**示例**：
- "修改部署脚本" → 自动找到并读取 scripts/rolling-deploy-hk.sh
- "修改 Nginx 配置" → 自动找到并读取 nginx/nginx.conf

### "查找 [关键词]"
```
自动流程：
1. Grep 搜索关键词
2. 显示匹配的文件列表
3. 询问要查看哪个文件
4. Read 读取选中的文件
```

## Git 操作

### "提交代码"
```
1. git status 查看修改
2. 生成符合规范的 commit message
3. git add 添加文件
4. git commit 提交
5. 询问是否推送
```

### "同步上游"
```
1. 检查当前分支
2. 执行 ./scripts/sync-upstream.sh
3. 处理冲突（如有）
4. 验证同步结果
```

### "创建 PR"
```
1. 检查当前分支
2. git diff 查看变更
3. 生成 PR 描述
4. 推送到远程
5. 提供 PR 创建链接
```

## 部署操作

### "部署到测试环境"
```
1. 检查当前分支（dev）
2. 运行测试
3. 构建镜像
4. 启动本地服务
5. 验证功能
```

### "部署到生产环境"
```
1. 确认在 dev 分支
2. 运行完整测试套件
3. 构建 amd64 镜像
4. 传输到服务器
5. 执行滚动部署（零停机）
6. 验证部署成功
7. 监控 5 分钟
```

### "回滚部署"
```
1. 连接到服务器
2. 查看可用的备份镜像
3. 执行回滚
4. 验证服务恢复
5. 记录回滚原因
```

---

## 测试操作

### "运行测试"
```
1. 询问测试类型（单元/集成/E2E）
2. 执行对应的测试命令
3. 显示测试结果
4. 如果失败，分析原因
```

### "修复测试"
```
1. 运行测试找到失败的用例
2. 读取测试代码
3. 读取被测试的代码
4. 分析失败原因
5. 修复代码或测试
6. 重新运行验证
```

## 文档操作

### "更新文档"
```
1. 询问要更新哪个文档
2. Glob 搜索相关文档
3. Read 读取文档
4. Edit 更新内容
5. 检查链接和格式
```

### "生成文档"
```
1. 询问文档主题
2. 检查是否有现有文档
3. 如果有，更新现有文档
4. 如果没有，创建新文档
5. 在 README 中添加索引
```

## 调试操作

### "查看日志"
```
1. 询问要查看哪个服务的日志
2. 连接到服务器（如果是生产环境）
3. 执行 docker logs 或查看日志文件
4. 分析错误信息
5. 提出解决方案
```

### "调试问题"
```
1. 询问问题描述
2. 搜索相关代码
3. 添加调试日志
4. 重现问题
5. 分析根因
6. 提出修复方案
```

---

## 代码审查

### "审查代码"
```
1. git diff 查看变更
2. 并行启动 3 个审查 agent：
   - Bug & Security Review
   - CLAUDE.md Compliance
   - Best Practices
3. 汇总审查结果
4. 提供修复建议
```

### "修复审查问题"
```
1. 读取审查报告
2. 逐个修复问题
3. 每次修复后重新审查
4. 直到所有问题解决
```

---

## 环境管理

### "启动本地服务"
```
1. 检查端口冲突（ops-engineer agent）
2. 启动 PostgreSQL 和 Redis（如未运行）
3. 启动后端服务（go run -tags embed）
4. 等待健康检查通过
5. 显示访问地址
```

### "停止本地服务"
```
1. 查找运行中的服务进程
2. 优雅停止服务
3. 验证端口已释放
```

### "重启服务"
```
1. 停止服务
2. 等待 3 秒
3. 启动服务
4. 验证健康检查
```

## 数据库操作

### "查看数据库"
```
1. 连接到 PostgreSQL
2. 显示所有表
3. 询问要查看哪个表
4. 显示表结构和示例数据
```

### "执行迁移"
```
1. 检查待执行的迁移
2. 备份数据库（生产环境）
3. 执行迁移
4. 验证迁移结果
5. 运行测试
```

## 监控操作

### "检查服务状态"
```
1. 连接到服务器
2. docker ps 查看容器状态
3. 检查健康检查
4. 查看最近的日志
5. 显示资源使用情况
```

### "查看性能指标"
```
1. 连接到服务器
2. 查看 CPU、内存使用
3. 查看数据库连接数
4. 查看 Redis 内存使用
5. 查看 Nginx 请求统计
```

## 自定义快捷方式

你可以添加自己的快捷方式：

```markdown
### "你的快捷命令"
\`\`\`
1. 步骤 1
2. 步骤 2
3. ...
\`\`\`
```

然后提交到 Git，这样 Claude 就能记住你的自定义命令了。

---

## 组合使用

你可以组合多个快捷方式：

```
"修改部署脚本，然后审查代码，最后提交"

Claude 会自动执行：
1. 修改 [文件名] 流程
2. 审查代码 流程
3. 提交代码 流程
```

---

## 注意事项

1. **快捷方式不是魔法**：Claude 仍然需要你提供必要的信息
2. **可以中断**：如果流程不符合预期，随时可以打断
3. **可以跳过步骤**：说"跳过测试"可以跳过测试步骤
4. **可以自定义**：根据项目需求添加自己的快捷方式
